# 품질 안전망 보강 — 요구사항

> 배경: 2026-08-18 세션에서 "석사학위논 문"(PDF 줄바꿈 오탈자) 버그를 사용자가 직접 발견해서 알려준 뒤에야 고침. 테스트가 없어 이런 종류의 "조용한 오작동"이 앞으로도 쓰다가 우연히 발견되는 방식으로만 잡힐 거라는 문제의식에서 시작.
> 관련 세션 메모리: `research_note_refparser_typo_fixes`, `feature_pdf_file_handle`

## 목표
개발자 관점 아쉬운 점(자동 테스트 없음)과 사용자 관점 아쉬운 점(PDF 원본이 폴더 한 곳뿐)을 실행 가능한 범위로 보완한다. "오류만 안 나면 괜찮다"는 체감을, 실제로 예방 가능한 수준으로 끌어올리는 게 목표.

## 범위

**이번 트랙에 포함**
1. 참고문헌 파서 회귀 테스트 (`refparser.js` / `refassembler.js`) — 화면 없이 계산만 하는 순수 함수라 테스트하기 쉽고, 오늘 실제로 버그가 난 부분이라 우선순위 1위.
2. PDF 백업 습관 안내 (쉬운 안) — 코드 거의 없이 도움말/안내 문구로 "논문 폴더도 가끔 따로 복사해두세요" 노출.
3. (여유 되면) PDF 백업 자동화 — 백업 버튼 눌렀을 때 텍스트 데이터뿐 아니라 PDF도 백업 폴더에 복사.

**이번 트랙에서 보류(하지 않음)**
4. 전체 화면 흐름 e2e 테스트(Playwright) — 첫 세팅에 반나절~1일 걸려서 목요일 하루 분량을 넘어감. 별도 세션으로 분리.
5. `app.js` 모듈 분리(리팩토링) — 테스트 안전망 없이 9천 줄을 건드리는 건 위험도가 큼. 1번(단위 테스트)이 어느 정도 쌓인 뒤에 다시 논의.

## 수용 기준 (이번 트랙이 "완료"라고 볼 수 있는 조건)
- [ ] `refparser.js`/`refassembler.js`에 최소 20개 이상 테스트 케이스 (학위논문·학술지·단행본·번역서·저자 다수 등 정상 케이스 + 오늘 겪은 것 같은 비정상 원문 케이스 포함)
- [ ] 테스트를 매번 수동으로 안 돌려도 되게, 간단한 실행 방법 확보 (`node` 로 한 줄 명령이면 충분 — 별도 프레임워크 설치 불필요)
- [ ] 테스트 실행 결과가 한국어로 통과/실패가 한눈에 보임 (사용자가 비개발자이므로)
- [ ] 도움말에 PDF 폴더 백업 습관 안내 문구 추가 확인
- [ ] (여유분 진행 시) 백업 버튼 눌렀을 때 PDF도 같이 복사되는지 실제로 확인 — 단, 매 자동 백업(1.5초 주기)마다 전체 PDF를 다시 복사하지 않는지 반드시 확인 (문제점 참고)

## 왜 이 순서인가 (우선순위 근거)
- 리팩토링(모듈 분리)을 테스트보다 먼저 하면, 안전망 없이 9천 줄을 손대는 셈이라 위험도가 가장 큼 → 뒤로 미룸.
- e2e 테스트는 가치가 크지만 셋업 비용이 하루 예산을 넘길 수 있어 별도 세션으로 분리.
- 참고문헌 파서 테스트는 (a) 오늘 실제 버그가 난 곳이라 동기가 명확하고 (b) 순수 함수라 테스트 작성이 가장 쉽고 빠르며 (c) 결과가 바로 눈에 보여 목요일 하루 안에 "완료"를 체감할 수 있음.
